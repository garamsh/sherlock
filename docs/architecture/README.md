# Architecture

Current architecture of the system and the decisions behind it. This file is the index; workers read it before touching code, the PM keeps it honest.

One pod per agent, two containers (ADR 0017): the agent container is the agent's self (gateway, reasoning loop, memory, mouth, tool client); the sidecar container is the agent's workspace — the computer: the gRPC data plane serving files and process execution. Tools are scripts the operator installs under `tools/<name>/` with a `manifest.json` and an executable; the platform owns the manifest format, the stdio call protocol, the boundary validation, and the drift pin. The code ships one binary with two subcommands (`sherlock agent`, `sherlock workspace`); first-party and third-party tools ship the same way, as `tools/<name>/` directories. Deployment artifacts live at `build/agent.Dockerfile` and `build/workspace.Dockerfile` (one image each, built by `make build-images`) and `deploy/local/`; the agent image carries the first-party tool executables at `/opt/sherlock/tools/` (ADR 0021), so no third image is built or pushed.

## Structure

- **Responsibility documents** (one `.md` per domain or concern) — the single source of truth for how the system is shaped *now*. To know the current state, read only these.
- **`adr/`** — the decision log: one record per current decision, numbered continuously from `0001` (`0000` is the template).

## Rules

1. **Responsibility document skeleton**: current decisions (consolidated) / rationale summary with links to the relevant ADRs / open questions. Do not copy ADR content — synthesize the present state.
2. **ADR records are living.** Each record states one current decision. When a decision evolves, update its record in place; when a decision stops carrying meaning, delete the record. History lives in git, not in the log. A record's date is its original decision date.
3. **Numbering is continuous.** A deletion or insertion renumbers the log, and references to renumbered records in other records are updated in the same PR.
4. **Decisions land in pairs.** A PR that adds or changes a record must update the affected responsibility documents in the same PR — the final state must always live in the responsibility documents.
5. Keep this index current: every responsibility document and ADR is listed here, and §Modules carries one row per Go package under `cmd/` and `internal/`. `tools/` and `tests/` take one row each, because a single statement holds for every package beneath them; the experiment harnesses under `research/` stay out, being no part of the shipped system. A package with no row is a defect in this file, not a judgement about the package.
6. **Structural rules live in `structure.md`.** The shape this project is partitioned into imposes rules — what the unit is, what may reference what, when a new one is earned — and they belong in the responsibility document for that concern, where a reviewer cites one by line and a correction is an ordinary edit. Not the ADR: the current state lives in the responsibility documents (rule 4), and the record holds why the shape was chosen, not the rules a reviewer applies.
7. **A point the structural rules leave to the project is settled in an ADR** — the one recording the shape where the question was met when the shape was chosen, a later one where it is met later. Which side is taken decides what counts as a defect, so it lands as rule 4 requires: the record and `structure.md`'s current decisions in the same PR. Nothing obliges the project to settle a question it has not met: until then the point waits under `structure.md`'s open questions, where it binds nothing, and moves into that document's current decisions when the project takes a side.
8. **Structural rules yield only to what a framework imposes.** Where `structure.md` and a convention file decide the same case differently, `structure.md` governs, unless the stack-specific file that applies decides it as its framework imposes it — the alternative fails to build or run, so the project cannot restate it. A stack file's spelling of a structural rule is not that: the rule it spells is `structure.md`'s. The shape this project chose is its own refinement of what a stack-neutral file states for every project.

## Index

### Responsibility documents

- `environment.md` — the environment splits into workspace (gRPC files and exec, the data plane) and tools (scripts with manifests, stdio contract): topology, execution, permissions
- `deployment.md` — what has to be true to run the workload as a pod: listeners and the bind gate, volumes, capabilities, startup failures, shutdown, snapshot and restore, images, and the facts an external consumer depends on
- `agent.md` — the agent is the self: reasoning loop, organs, platform tool client, model access
- `memory.md` — long-term memory: the agent's organ — store, reads, lifecycle
- `gateway.md` — the agent's ears and eyes: ingress, outbound, monitoring
- `security.md` — trust domains, secret custody, egress, tool-trust posture
- `structure.md` — the structural rules of the domain shape: what a unit is and is named for, what may reference what, where concrete implementations are constructed, where shared code goes, when a new domain is earned
- `packages.md` — the package partition: which layout of `stack-go.md` §Directory layout this project is under, the three cuts that produce every package, which way imports run across them, and where a new package goes

### Decision log

- `0001` — Go stack and single-module layout
- `0002` — per-agent memory in a single SQLite file
- `0003` — secret-free execution domain
- `0004` — model access is consumer-owned interfaces, and the wire protocol is configuration
- `0005` — tools own security; guard models are layers, not boundaries
- `0006` — preserve recent context and source-linked older conversation
- `0007` — gateway I/O: a platform-neutral gateway with pushed asynchronous ingress, tool-based outbound, separate monitoring
- `0008` — agent-influenced sub-processes run dropped to the unprivileged UID
- `0009` — the tool definition shape: a script with a manifest
- `0010` — one execution boundary: agent-influenced effects under the unprivileged UID
- `0011` — persist sources before atomic summary checkpoints, and keep one bounded note beside them
- `0012` — gateway authentication via mTLS
- `0013` — external egress is tool-routed
- `0014` — scope boundaries: authorization above the platform, no mid-run intervention
- `0015` — the turn drains the queue
- `0016` — the identity is the agent ID
- `0017` — the agent is the self; the workspace is the data plane; tools are scripts with manifests (pod-per-agent)
- `0018` — a retrieved memory carries a path to its source
- `0019` — recall older conversation by embedding similarity and an entity walk beside recency, and let the agent search again during work
- `0020` — the image repositories are immutable, and a consumer references an image by digest
- `0021` — first-party tool executables are baked into the sherlock-agent image; no separate sherlock/tools image is published
- `0022` — the running agent reports what it loaded, and drains its in-flight turn on SIGTERM
- `0023` — the system is partitioned by domain, and a domain depends on a sibling one way through its declared surface
- `0024` — operator instructions are a separate optional file, placed between the ego and the platform contract
- `0025` — a start may require the memory store to exist, and refuses one that is absent or uninitialized
- `0026` — an inbound message is accepted on the signature of an issuer the agent is configured to trust
- `0027` — the workspace's operations are `sherlock workspace` subcommands that reach it only through its listener
- `0028` — `sherlock workspace mcp` is a stdio MCP server whose tools each run one workspace CLI operation as a child process
- `0029` — the model credential is a file Sherlock re-reads

### Modules

| Path | Responsibility | Topic file |
|---|---|---|
| `cmd/sherlock/` | CLI entry point (`sherlock agent`, `sherlock workspace` and its operation subcommands `read`, `write`, `list`, `exec`, and `sherlock workspace mcp`): build the command tree, resolve settings through `internal/config/`, and hold the provider wiring that turns them into concrete implementations, the model key file read for every request among them (ADR 0029). It keeps the startup decisions that read a resolved setting and belong to no one boundary — where logs go, whether an address may be served at all under ADR 0012, and how long the tool registry lives. It holds the workspace operations' client: one call on the listener per invocation through the wire in `internal/workspace/`, the result on stdout, and the exit status and stderr object that tell a workspace's refusal from an unreachable workspace (ADR 0027). It holds the workspace MCP server too: a stdio server, over `github.com/modelcontextprotocol/go-sdk`, whose tools each exec this binary as one operation subcommand and map its exit class onto the MCP answer (ADR 0028). | — |
| `internal/config/` | Resolve the settings both entry points run on, in one precedence — flags, `SHERLOCK_*` environment, config file, defaults — and register the flags that are its own top layer, so a caller cannot reach the resolution with the wrong flag set. The workspace operations' one setting, the listener address, resolves in the same precedence without the file layer (ADR 0027). Holds the resolved types the commands pass down, the reading of the ego and operator-instructions files (ADR 0024), the gateway's TLS material (ADR 0012), the trusted issuers and `require-signature` (ADR 0026), the refusal of a model section naming both `api-key-file` and `api-key-env` (ADR 0029), and the two startup gates gating on a resolved value: the owner-only rule for operator files, and the loopback-bind predicate both listeners refuse a non-loopback address with. | — |
| `internal/gateway/` | Accept normalized inbound messages over HTTP — verifying a message's signature against the trusted issuers' cached key sets and taking its sender from it (ADR 0026) — serialize the one agent's runs through a single queue that drains a batch per turn, publish the monitoring event stream as SSE, and report the process's status. It runs the HTTP listener and its shutdown — the drain that finishes the turn in flight before memory closes (ADR 0022) — and runs the one-shot turn for a caller that is not serving — reading the outbox to report what the turn delivered, and collecting the turn's failed tool calls so the caller's exit status can carry them. It also holds the runtime composition root: the factory that opens the agent's memory store, wires the session's lifecycle hooks, and assembles the rolling session a turn runs on. `cmd/sherlock/` builds that factory from the resolved settings, but the store, the hooks and the session are constructed here — so concrete construction is split across two packages, the part `tests/` must reach sitting where they can reach it, as `stack-go.md` §Project envelope allows (`packages.md`). | `gateway.md` |
| `internal/agent/` | Run the rolling reasoning session and its tool budget, terminal response call with the agent's note, source-linked memory search and inspection calls, event stream, and model and embedder interfaces. It persists completed visible turns through the memory boundary and restores recent conversation supplied by the runtime. | `agent.md`, `memory.md` |
| `internal/agent/anthropic/` | The chat-model implementation of the agent's model interface, over Anthropic's Messages API at the operator-configured base URL (ADR 0004). A second wire protocol rather than a second vendor: it absorbs what that protocol places differently — the system prompt, the carrier a tool result travels on, and a token ceiling the protocol requires — and sends each tool's schema unmodified, so it holds no strict-mode projection. Like the chat-completions client, it reads a re-readable credential for every request, retries a 401 once after reading it again (ADR 0029). | `agent.md` |
| `internal/agent/memory/` | Provide context compaction, episodic model synthesis naming each batch's entities, and bounded recent, similar, entity-linked and pending conversation recall with no model call. | `agent.md`, `memory.md` |
| `internal/agent/openai/` | The chat-model implementation of the agent's model interface, over the chat-completions API at the operator-configured base URL, and the embedder implementation over the embeddings API at its own configured base URL (ADR 0004). Holds the strict-mode projection of each tool's schema that the wire request carries — a provider-local view, not the tool boundary. The chat client reads a re-readable credential for every request, retries a 401 once after reading it again (ADR 0029). | `agent.md` |
| `internal/tool/` | The platform tool client: read manifests from the operator's `tools/` directory, spawn the executable, validate inputs and outputs against the manifest's JSON Schemas, hold each manifest hash against the operator's pin set to refuse drift at startup, and fail closed when a required tool is missing (ADR 0017, ADR 0009). It also names the environment variables the spawn contract carries to every tool, and publishes their values — the turn's drained message IDs per call, from the call's context; a tool's credentials are not among them (ADR 0003). | `agent.md`, `environment.md` |
| `internal/tool/tooltest/` | Test guards for the shipped tools' contracts: read `tools/<name>/manifest.json`, split its input and output schemas, check each parses as a JSON Schema whose `required` names properties that exist, and check a schema against the Go struct it must match. Shared by the tests of the packages that own those structs. | — |
| `internal/memory/sqlite/` | Own `memory.db`: the per-host writer lock taken before it opens, the source archive, immutable mid episodes and their embeddings and entity links, similarity ranking and the entity walk, resumable four-message cross-turn batching, atomic checkpoints, linked reads, and the agent's note. Refuse populated old data, the addressed rows of an earlier design among it, at runtime without changing it, and, for a start that requires it, a store that is absent or uninitialized (ADR 0025). | `memory.md` |
| `internal/message/` | The outbound message type — the entry's opaque ID and creation time, the sending agent, its provenance labels, the messages it replies to, channel, target, content. The package carries no delivery code, because delivery is that write. | `gateway.md` |
| `internal/workspace/` | The gRPC data plane's wire: the proto and the generated stubs, and nothing else — a tool that needs the workspace imports this package and links no backend (#525). | `environment.md` |
| `internal/workspace/server/` | The data plane's server side: the `Server` wrapping the workspace filesystem backend for Read/Write/List and `internal/workspace/shell.Executor` for Exec (ADR 0017), and the listener's lifecycle — bind, serve, graceful stop, the single-account environ protection and the root handover to the exec account. It relabels every filesystem error as `InvalidArgument` and turns an executor timeout into a normal response. No tool hosting. | `environment.md` |
| `internal/workspace/shell/` | The workspace's exec backend behind the Exec RPC: fork+exec+setuid dropped to the exec UID (ADR 0008), scrubbed child environment (ADR 0003), per-request network isolation, and the trust class that decides whether resource caps bind at all (ADR 0010); two fail-closed sentinels, `agent_uid unavailable` and `resource limits unavailable`. It owns two things that are not behind the RPC: `ProtectEnviron`, which marks the workspace process itself non-dumpable (ADR 0003), and the `exec-limits` shim — an argv verb of the platform binary, dispatched in `cmd/sherlock/` before the command tree, that caps itself and execs the child. | `environment.md` |
| `internal/workspace/files/` | The workspace's filesystem backend (single-consumer of the sidecar; lives here per the layout rules): an FS rooted at the workspace directory which enforces the lexical confinement itself, and the ownership handling exec children need (ADR 0008, ADR 0010) — handing the root to the exec account with a shared-group write bit, writing through a temp file and an atomic rename so a file that account owns can still be replaced, and propagating ownership to the directories it creates. | `environment.md` |
| `tools/` | The tool set the operator installed. Each tool is a directory `tools/<name>/` holding `manifest.json` (the contract) and a Go package (the implementation); `make build-tools` compiles the executable the platform spawns into that directory, where `.gitignore` keeps it out of the tree. First-party tools ship here, and `build/agent.Dockerfile` copies the same set into `/opt/sherlock/tools/<name>/` of the sherlock-agent image at build time (ADR 0021, `deployment.md` §Images and tags). | `agent.md`, `environment.md` |
