# Agent

Governs the agent: the reasoning loop, tool use, and model access. Rationale: ADR 0005, ADR 0008.

## Current decisions

- The agent runs one continuous rolling session per environment — a person model, not a task-runner model. No automatic resets.
- Context is organized around the current task. Each turn follows the memory lifecycle: frame, recall, act, writeback.
- The reasoning loop is model call → tool-call decision → execution → result incorporation → repeat. The agent reads the registry's tool schemas and decides on its own when to call which tool.
- A tool call that already failed twice in the same turn with the identical error — exact match on name, input bytes and error text — is not executed a third time. The execution step is substituted with a synthetic result telling the model the call failed identically and that it must change approach or finish; the call still emits a failed `tool_call` event. The bookkeeping is per-turn, and the iteration cap remains the backstop.
- Memory decisions (store, update, compress, forget) are the agent's own, made inside the reasoning loop via the memory tool and the writeback block. No separate memory-manager component exists.
- Outbound replies are the agent's decision through the `message_send` tool; default reply conventions live in the agent's instructions.
- All LLM access goes through narrow interfaces owned by the consumer: a model interface (agent loop) and an embedder interface (memory). The scripted mock model and a hashing-based embedder keep the full pipeline runnable offline; a real OpenAI-compatible chat provider (`internal/agent/openai/`) is selected via the `model` config section.
- The loop, session, `Model` interface, lifecycle hook interfaces (`Recaller`, `WritebackSink`, `Compactor`, `EventSink`), and the scripted mock model live in `internal/agent/`. The writeback block is a trailing ` ```memory ` fenced JSON block carrying `keep` / `update` / `delete` / `add` operations. The parser is strict on operation-schema violations (e.g. keep with empty id) — those fail the turn so the model learns the contract — but lenient on parse failures (unterminated fence, invalid JSON): the visible reply still reaches the user, the memory update is dropped for that turn, and the miss is logged at WARN level and surfaced as an `EventWritebackError` event (issue #93).
- The session injects its instructions — ego plus platform contract — as the first system message of a fresh session. The ego (identity, behavior guidance) is operator-owned and file-based: the `--ego-file <path>` flag selects a file, otherwise the embedded `internal/agent/EGO.md` (`agent.DefaultEgo`) is used; a missing or unreadable file fails at startup. The contract (tool use, writeback format, reply conventions) is protocol versioned with the code (`agent.Contract`), appended by the platform to every session's instructions (`agent.ComposeInstructions`) and never overridable by an ego file, so a custom prompt cannot break the memory loop. The ego path is flag-only — deliberately not a config key.
- The OpenAI-compatible provider (`internal/agent/openai/`) maps conversation and tool descriptors onto the chat-completions API — tool calls and finish reasons map back to `agent.Response`. Any OpenAI-compatible endpoint (Ollama, vLLM, …) works through the configurable base URL; the API key is read from the environment variable named by config, never from the config file (ADR 0004). Tool input schemas double as function-calling parameter documents, so every built-in schema must stay inside the API's accepted top-level subset (`type: "object"`; no top-level `allOf`/`anyOf`/`oneOf`/`not`/`enum`/`const`) — conditional validation lives under `if`/`then` instead, and a runtime test (`internal/agent/openai/openai_test.go` + `tests/e2e_test.go`'s built-in subset assertion) guards the constraint. The four built-in tools are `memory`, `files`, `message_send`, and `shell_exec` (ADR 0012); the per-tool guard still applies to each. `shell_exec` runs agent-supplied commands as sub-processes of the platform binary, dropped to the agent UID per ADR 0006; when the platform cannot drop privileges it returns `agent_uid unavailable` and the agent falls back to the three typed tools.
