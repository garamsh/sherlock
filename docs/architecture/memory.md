# Memory

Governs long-term memory: the store, the reads it answers, and the lifecycle. Rationale: ADR 0017, ADR 0006, ADR 0011, ADR 0018.

## Current decisions

- Memory is the agent's long-term organ — a layer inside the agent container, never exposed as a tool (ADR 0017). The model touches memory only through the lifecycle below.
- The store is one SQLite file per agent in the agent container's volume, behind a store interface that hides SQLite so a remote or shared store can replace it later. The per-agent store carries forward from the pre-pod design; the memory-UID custody dissolves because no untrusted code runs in the agent container.
- The store is **curation-only**: the model writes through the writeback and nowhere else (ADR 0006, ADR 0011). There is no platform auto-capture of inbound messages — a message the model never states as a fact never enters long-term memory.
- Salience is platform-derived from the operation the write states, never model-written: a replacement ranks highest and a value joining what is held ranks high (ADR 0006).
- **A fact is held at the address of the question it answers, and the write states whether a value replaces what is there or joins it** (ADR 0018). Identity is computed, never inferred from similarity; where a writeback must err, it errs toward join, because a wrong join is repaired by the next correct replacement at that address and a wrong replacement is repaired by nothing.
- Memory is three parts, not one (ADR 0018): a writeback that reads a sentence into an address, a store that holds an address and a value, and a read step that reads a question into an address. The store does no finding — asked in words, an addressed store answers nothing, so the read step in front of it is not an optimization.
- **A question becomes an address before the store is read, and a read that finds nothing there widens to the subject** (ADR 0019). The read step resolves into the writeback's own vocabulary rather than a richer one, because a read reaches a fact only by computing the address the write chose; where a read must err it errs toward the wider address, since a question the write never used returns nothing and says nothing, while a subject read returns the answer with company.
- Forgetting is decided by use rather than by age or by the write (ADR 0018). An age-ordered rule discards the oldest fact, which is the one a decade of turns never re-asserts and a question still asks for.

Two of the three parts above run. The writeback states an address, a value and an operation in the reserved tool call a turn ends on (#336 step 1, #615), and the store holds an address and a value (#336 step 2). The read step is #336 step 3: it is **designed and not built** (ADR 0019), so **the agent recalls nothing** — `internal/gateway` wires no `agent.Recaller`, a turn emits no recall event, and the store answers only a caller that already has an address. §Current state (as implemented) is what runs today.

## Current state (as implemented)

- **Store** — one `memory.db` per agent at the configured `memory-path`, holding an address and a value and nothing else: no sentence, no embedding, no keyword index (ADR 0018). Active and archive tables; the platform never hard-deletes. One unique index on `(subject, question, restriction, value)` carries every read and holds a value once at its address. The memory-UID custody is gone: no untrusted code runs in the agent container (ADR 0017).
- **A store written before #582 is not opened.** It holds sentences, and an address cannot be computed from one without a model call, so there is no migration to offer. `sqlite.Open` reports it as a distinct startup failure rather than failing later on a missing column.
- **Reads** — two, and both take an address rather than words. Asking an address returns the values held there and, where the address restricts nothing, the values at every address restricting the same question — a narrower question is a question about the same thing, and without that relation a restricted value would sit where nothing asks for it. Asking a subject alone returns every address under it. Neither is ranked and neither is trimmed: the store holds no score, and the ordering a question spanning several addresses would need is not in the record (ADR 0018 §What is not measured), so where the answer is more than fits it returns more than fits.
- **The agent recalls nothing, and that is this step's cost.** The store does no finding — asked in words, an addressed store answers nothing at all (ADR 0018) — and the step that reads a question into an address is #336 step 3. It has a design and no implementation (ADR 0019): no `agent.Recaller` is wired, no recall event is emitted, and nothing reaches the model's context from memory. The writeback still stores every fact a turn states, so what step 3 arrives to read is already there.
- **Write** — one operation, `Store`, and the operation the write states decides what happens to the values already at the address: a replacement supersedes them, a join leaves them. Nothing compares the new value with what is held. A replacement supersedes only the address written, so a narrowing statement never destroys the question it narrows.
- **Identity is computed, and similarity is absent rather than weakened** (ADR 0006 §Decision, ADR 0018). There is no embedder, no cosine and no threshold in `internal/memory/` to tune: the mechanism `docs/experiments/memory-retrieval/` refuted — no threshold separates a correction from two facts that must both survive — has nothing left to read. The `#529` failure it caused is gone with it: two facts about one subject are two addresses.
- **Salience and retention** — salience is derived from the operation, so every value the writeback stores is `0.8` (a replacement) or `0.7` (a join). Both are at or above the keep tier, **so the retention pass now drops nothing a writeback wrote**. The tier it dropped was the episodic one and nothing writes it any more; the pass still runs after a completed turn and still drops a lower-salience row, so what changed is what reaches it (ADR 0006).
- **No episodic memories, no compression, no consolidation.** An addressed store has nowhere to put a sentence it cannot address, and a summary of a conversation answers no question a read can ask for. The context-overflow write was their last source and it is gone; compaction keeps the newest messages and writes nothing. On the configuration this repository ships as its worked example the write already never happened — it was refused unless a model generated the summary, and the deterministic stand-in does not (#549) — so what such an operator holds is unchanged.
- **No write-time coherence.** ADR 0006 step 5 surfaced the most similar existing memories for the model to judge, which is what a store that could not compute which memory a write was for needed. The address computes it and the stated operation says what to do about it, so the note has nothing left to ask.
- **Maintenance** — capacity eviction uses the ranking score, which is now salience plus a salience-scaled Ebbinghaus decay and no relevance term, because an addressed read reaches its address without scoring anything. Nothing evicts at the capacities a decade of turns reaches (`docs/experiments/memory-frames/`).
- **Forgetting is not yet decided by use.** ADR 0018 chose a least-recently-read rule, and the store records what a read touched — every read writes `access_count` and `last_accessed` — but nothing reads those columns back: eviction orders by salience and write age, which is the age-ordered rule that record measured losing the `carried` class entirely. #582 built the store rather than the eviction, and the two columns are there for the rule that has not been written.
- Memory is never a tool: the model touches memory only through the lifecycle — the writeback is the model's single write path (ADR 0011, ADR 0017). ADR 0011 scopes that to the model's own surface: it unified two paths the model chose between, and it leaves platform mechanics — threshold-triggered, never model-invoked — outside. Eviction and retention are that category.

## Open questions

- Snapshot/backup of the memory file outside the pod — default post-MVP.
- Cross-agent shared memory — deferred.
- Benchmark-based evaluation harness — the read path is measured against a planted corpus with known ground truth under both embedders, and the supersession threshold against the pair set that refuted it (`docs/experiments/memory-retrieval/`); the shipped store is measured over a decade of turns beside sixteen other structures (`docs/experiments/memory-frames/`), including what a real model extracts from a message, what it declares about an assertion, and what address it reads a question onto. No benchmark runs against a live agent's store, and no run measures whether a model writes back at all — that is `docs/experiments/memory-cycle/`'s subject.
- What a writeback does with a declaration it cannot trust (ADR 0018). Taking a model's declarations and always replacing are a genuine trade, and which failure is cheaper is a property of what the agent is for rather than of anything measured.
- Whether a model asked for a restriction invents one. Asked in the form the write now uses — give the restriction the statement places on the question, empty where it places none — a model supplied one on nearly every assertion that placed none, which is what collapses whole-address accuracy while the question itself stays right (`docs/experiments/memory-frames/` §Whether the address carries the arity). The forms that might not do this — a closed set of restrictions, or asking whether the statement narrows anything before asking what it narrows — are named there as different measurements, and none is measured.
- What the read step costs resolving into a question-shaped address space. It was measured resolving into the topic space, because that is the space it ran in (ADR 0018), and that run was handed the twelve attribute names it chose among — a closed vocabulary a question-shaped address does not have (`docs/experiments/memory-frames/harness/resolve.go`). ADR 0019 decides the step's shape on that gap rather than closing it, and every accuracy it implies is a design expectation.
- What the read step returns when a question reaches more addresses than fit. An addressed store has no ordering over the addresses under a subject and no budget to answer inside; where an ordering would have to live is the read step (ADR 0018). ADR 0019 defers one rather than specifying it — an ordering is a ranking with constants nothing calibrates — and names the condition that would reopen it: a subject read observed in production to exceed the budget.
- Whether tiered retention should run from a memory's last use rather than from its writing. The window is wall-clock and runs from the timestamp, so an idle agent drops every mid-salience memory on the turn that ends the idleness and a slow agent keeps one for a handful of turns (ADR 0006). `docs/experiments/memory-frames/` §What decides the eviction is the nearest evidence and it does not decide this: it compared last-read-time against write-age and found the age-ordered rule loses the `carried` class entirely (`0.000` against `0.775`–`1.000` for least-recently-read), but it measured which memory to discard once a hard capacity bound bites, and the same record states that capacity eviction never fires in either arm of the decade run. It measured no retention window and no turn-counted rule. Moving retention onto last use is a policy change that record does not reach, so #510 left the mechanism where it was and recorded the question here.
- Whether write-time coherence survives. The step retrieves the most similar existing memories on every write and presents them for the model's judgment (ADR 0006), which is what a store that could not compute where a fact belongs needed; a store that computes its address has no stated role for it. `docs/experiments/memory-frames/` measures nothing about it — its seam has no such step — so nothing here says whether removing it would cost anything. Whether it survives belongs to #336's design.
