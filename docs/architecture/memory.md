# Memory

Governs the agent's source-linked conversation memory and its lifecycle. Rationale: ADR 0002, ADR 0006, ADR 0011, ADR 0018, ADR 0019.

## Current decisions

- The rolling session keeps the newest visible conversation for current work. It is bounded by the configured message limit; `internal/agent/memory/compaction.go` keeps the leading instruction and trims the oldest window entries. A negative limit disables compaction and restores all saved visible messages after restart.
- Completed turns write each original inbound user message with its gateway ID, successful outbound `message_send` content, and the terminal assistant reply to the agent's SQLite file. System instructions, tool results, hidden reasoning, and credentials are outside the durable source boundary. Credential patterns are redacted before persistence; a redacted original cannot be recovered verbatim (ADR 0006).
- The recent rolling window is short memory. There is no separate short-summary tier. A full batch of four completed visible messages across turns produces one immutable mid episode, synthesized by the session model independently of other episodes. Partial batches remain durably pending (ADR 0006).
- Source capture commits before synthesis. Each mid episode commits its direct source interval atomically; the end of the latest committed interval is the processing checkpoint. Failed synthesis leaves pending sources for the next completion or startup to retry, without holding a database write transaction across the model call. Each episode's summary embedding is stored with it in the same file once it commits; a failed embedding is retried the same way, and the episode is left out of similarity ranking until then (ADR 0011, ADR 0002).
- Recall combines the two newest mid episodes with up to five more ranked by cosine similarity between the task text's embedding and each summary's, deduplicated by ID, recent first, with no model call before the act loop. There is no threshold. A page of up to four pending source previews remains visible even with a small rolling window (ADR 0019).
- During the act loop the reserved `memory_search` call ranks mid episodes by cosine similarity to a query the model writes, at most five per call and bounded by the per-tool budget of six calls a turn. It returns each episode's summary with its source interval (ADR 0019).
- The agent keeps one note of at most 2,000 characters in the same file. The model restates it whole in every terminal call; a string replaces it and a note left out or null keeps it. The note is saved after the turn's sources, with credential patterns redacted, and shown under the instructions on every turn, so neither compaction nor a restart drops it. It is model-written and unlinked to sources: it states what the agent keeps, not verified evidence (ADR 0011).
- The reserved `memory_inspect` call reads an exact source message by ID directly from an episode's inclusive source interval. Summary text is a retrieval hint, not verified evidence. Corrections can supersede assertions within an episode; across episodes, chronology and original evidence distinguish current from historical claims (ADR 0018).
- The same SQLite file still contains the addressed tables of the previous design. The runtime refuses startup when those tables hold active or archived rows, with `ErrAddressedStore`; it does not reinterpret or delete them. An explicit export or migration is required to run source-linked recall on that file (ADR 0002).

## Current state

`internal/gateway/runtime.go` opens the store, checks old data, restores the newest persisted visible messages into the rolling session, retries pending full batches, and wires synthesis, the embedder, recall, search, inspection and the note. A completed response persists its source records before summary maintenance and `turn_finished`; maintenance failure reports an error while retaining those sources. The source archive is durable across a clean restart and does not depend on the bounded session window. The store keeps each bounded mid summary's embedding beside it and ranks them in process; original source text is reached through IDs after a candidate is found.

The `memory_write` transport carries the reply and the note; the addressed `memory_ops` field and its unwired sink are gone. The monitoring stream's `writeback` event carries the saved note as `note`, and leaves the field out when the turn kept the note; the `ops` field it carried before is gone. The source-linked conversation store and the note are the only active long-term memory, both in the agent's SQLite file.

## Existing databases

- A source-linked database from before embeddings opens in place: startup drops its FTS5 index and trigger, adds the embedding column, and embeds every stored episode before the first turn. An embedding failure stops startup, as a synthesis failure does; episodes and their intervals are unchanged, and those still without an embedding are embedded at the next start. Episodes synthesized at batch 8 keep their intervals and stay readable; only new batches hold four messages. `TestOpenConversation_EmbedsEpisodesFromBeforeEmbeddings` covers this.
- A file from before the note opens in place: startup creates the `conversation_note` table, the note starts empty, and the conversation is unchanged (`TestNote_DatabaseFromBeforeTheNoteOpensWithAnEmptyNote`).
- Stored embeddings belong to the model that wrote them. Recall refuses a file whose vectors differ in length from the configured model's with an error naming the model change. A different model of the same length is not detected and ranks by incomparable vectors, so keep one embedding model per memory file.
- Populated extractive source-linked databases are refused before modification. Their one-source summaries are not silently reinterpreted as episodic summaries. Empty extractive schemas upgrade automatically; populated legacy addressed tables retain their startup refusal.
- Stop the old process cleanly and retain the old binary and the complete database, including any WAL/SHM sidecars if shutdown was interrupted. Back up with SQLite's backup facility or while no process is writing; copying only the main file during an active WAL write is not a backup.
- To start episodic memory without rewriting old evidence, select a different, empty `--memory-path`. Keep the original file with the previous binary for historical inspection. The new runtime does not search that separate archive. Carrying all old history into the new runtime requires an explicit migration; none is provided here. Do not delete or relabel the old summary tables to bypass the refusal.
- `TestOpenConversation_ExtractiveDatabaseRequiresExplicitNewPath` verifies refusal leaves the populated file unchanged and that the fresh-path and empty-schema controls work.

## Open questions

- Pre-turn recall has no threshold, so it cannot report that nothing relevant exists, and neither can a search. Whether the model searches when it should is the model's choice, and the note holds only what the model writes into it. The runs in `docs/research/agent-context/` measured both on one model and a templated corpus; the third, on unmixed evidence batches (#870), found them valid against the shipped recall (ADR 0011, ADR 0019).
- Recall reads every embedded episode on each turn and ranks them in process, so its cost grows linearly with stored episodes, one per four messages; no index bounds it.
- The batch is its own constant of four messages, independent of the rolling window's message limit. Whether one size should set both is with the owner.
- Synthesis can omit facts or mishandle corrections; an episode summary is model output, not verified truth. Bounded similarity retrieval can also omit evidence. Deterministic tests exercise persistence, correction fixtures, linking, and context bounds; they do not establish general model fidelity.
- Pending source previews are bounded; unusually long messages require exact source inspection. A persistent model failure prevents startup catch-up until the provider recovers, while completed sources remain intact.
- Gateway source IDs make retries of the same completed input batch idempotent. One-shot calls without IDs are distinct turns, so an uncertain acknowledgement cannot be deduplicated from text alone. Mixed previously committed and new IDs are refused rather than silently skipped.
- Credential redaction recognizes common labelled and bearer forms, not every possible secret syntax. Deployments should avoid sending credentials in conversation.
- An in-flight turn that fails before source capture has no durable assistant reply. Accepted but undrained gateway messages remain process-local (`gateway.md`).
