# Memory

Governs durable memory: the store, the reads it answers, and the lifecycle. Rationale: ADR 0017, ADR 0006, ADR 0011, ADR 0018.

## Current decisions

- Memory is the agent's long-term organ — a layer inside the agent container, never exposed as a tool (ADR 0017). The model touches memory only through the lifecycle below.
- The store is one SQLite file per agent in the agent container's volume, behind a store interface that hides SQLite so a remote or shared store can replace it later. The per-agent store carries forward from the pre-pod design; the memory-UID custody dissolves because no untrusted code runs in the agent container.
- The addressed fact store is **curation-only**: the model writes through the writeback and nowhere else (ADR 0006, ADR 0011). There is no platform auto-capture of inbound messages — a message the model never states as a fact never enters long-term memory.
- Salience is platform-derived from the operation the write states, never model-written: a replacement ranks highest and a value joining what is held ranks high (ADR 0006).
- **A fact is held at the address of the question it answers, and the write states whether a value replaces what is there or joins it** (ADR 0018). Identity is computed, never inferred from similarity; where a writeback must err, it errs toward join, because a wrong join is repaired by the next correct replacement at that address and a wrong replacement is repaired by nothing.
- Addressed fact memory is three parts, not one (ADR 0018): a writeback that reads a sentence into an address, a store that holds an address and a value, and a read step that reads a question into an address. The store does no finding — asked in words, an addressed store answers nothing, so the read step in front of it is not an optimization.
- **A question becomes an address before the store is read, and a read that finds nothing there widens to the subject** (ADR 0019). The read step resolves into the writeback's own vocabulary rather than a richer one, because a read reaches a fact only by computing the address the write chose; where a read must err it errs toward the wider address, since a question the write never used returns nothing and says nothing, while a subject read returns the answer with company.
- Forgetting is decided by use rather than by age or by the write (ADR 0018). An age-ordered rule discards the oldest fact, which is the one a decade of turns never re-asserts and a question still asks for.

All three parts run. The writeback states an address, a value and an operation in the reserved tool call a turn ends on (#336 step 1, #615); the store holds an address and a value (#336 step 2); and the read step turns the turn's task into an address before the store is read (#336 step 3, #630). §Current state (as implemented) is what runs today.

## Current state (as implemented)

- **Current work** — one revisioned singleton in the existing database, outside fact lookup and retention. The session owns its lifecycle (ADR 0006); the memory domain defines its types and persistence contract, and SQLite implements it. The record holds the exact initial arrival and retained amendments as source, one current arrival, a lifecycle account with subordinate progress, and individually identified attempts. Schema creation adds it to an existing addressed store without resetting facts or archives. The prior unshipped summary and optional-source formats cannot reconstruct original intent they discarded. The indexed-input format retained initial source but could leave corrections unapplied; converting it cannot establish which instructions governed. All three are refused, and measured databases remain inspection evidence. Invalid documents and unsupported versions fail startup, and stale or failed replacements fail the turn.

- First-source capture is unconditional. Later arrivals become exact source by default, without model selection; an interrupted arrival survives the next arrival. Curation can dismiss only the current neutral arrival. Replacement with active status retires prior source and stale progress; a fresh idle source also retires after its own successful fact-only writeback with no attempted effects. A later fact cannot retire older source. This preserves addressed facts without expanding their recall boundary.
- Terminal curation is optional: omitted, null or unreadable updates retain the entire record, as do dismissal without a current arrival and idle proposals for active work. A diagnostic distinguishes fallback from applied curation. Invalid replacement, terminal revival and unsupported attempt retirement remain failures. Reply and fact validation permits one terminal-only correction without dispatching further operator calls; exhausted repair preserves durable evidence and fails visibly.
- One lifecycle status controls operator access. Attempts activate idle work; terminal work refuses operator calls and status changes until explicit replacement is persisted. No progress note can reopen it. Recognizing natural-language cancellation or new authorization still belongs to the model. Retained arrivals and unretired observations have no fixed bound; neutral traffic missed by curation remains until task replacement (ADR 0006).

- **Store** — one `memory.db` per agent at the configured `memory-path`, holding the current-work account alongside addressed fact tables; those fact tables hold an address and a value: no sentence, no embedding, no keyword index (ADR 0018). Active and archive tables; the platform never hard-deletes. One unique index on `(subject, question, restriction, value)` carries every read and holds a value once at its address. The memory-UID custody is gone: no untrusted code runs in the agent container (ADR 0017).
- **A store written before #582 is not opened.** It holds sentences, and an address cannot be computed from one without a model call, so there is no migration to offer. `sqlite.Open` reports it as a distinct startup failure rather than failing later on a missing column.
- **Reads** — two, and both take an address rather than words. Asking an address returns the values held there and, where the address restricts nothing, the values at every address restricting the same question — a narrower question is a question about the same thing, and without that relation a restricted value would sit where nothing asks for it. Asking a subject alone returns every address under it. Neither is ranked and neither is trimmed: the store holds no score, and the ordering a question spanning several addresses would need is not in the record (ADR 0018 §What is not measured), so where the answer is more than fits it returns more than fits.
- **Recall is one model call in front of the store** (ADR 0019). The store does no finding — asked in words, an addressed store answers nothing at all (ADR 0018) — so the read step resolves the turn's task into an address first, in the write's own vocabulary: both halves embed one account of what an address is, so neither can grow a rule the other lacks. It asks for no restriction, which reads the address and every restriction under it.
- **The order is fixed and carries no threshold**: resolve, read the address, and read the subject only where the address held nothing. The widening fires on emptiness, which the store reports for one indexed read and no model call, rather than on a confidence, which would be a constant nothing calibrates.
- **Four outcomes, and the stream carries which.** A question the step could not place (`unplaced`), an address that answered (`addressed`), an address that held nothing and a subject that answered (`widened`), and nothing held anywhere (`empty`). A question memory could not place is not a question memory had no answer to: the model is told them apart and so is the recall event, which is the instrument the design's accuracy is measured through — `docs/experiments/recall-specificity/` scored the running agent's read step from it.
- **Write** — one operation, `Store`, and the operation the write states decides what happens to the values already at the address: a replacement supersedes them, a join leaves them. Nothing compares the new value with what is held. A replacement supersedes only the address written, so a narrowing statement never destroys the question it narrows.
- **Identity is computed, and similarity is absent rather than weakened** (ADR 0006 §Decision, ADR 0018). There is no embedder, no cosine and no threshold in `internal/memory/` to tune: the mechanism `docs/experiments/memory-retrieval/` refuted — no threshold separates a correction from two facts that must both survive — has nothing left to read. The `#529` failure it caused is gone with it: two facts about one subject are two addresses.
- **Salience and retention** — salience is derived from the operation, so every value the writeback stores is `0.8` (a replacement) or `0.7` (a join). Both are at or above the keep tier, **so the retention pass now drops nothing a writeback wrote**. The tier it dropped was the episodic one and nothing writes it any more; the pass still runs after a completed turn and still drops a lower-salience row, so what changed is what reaches it (ADR 0006).
- **No episodic memories, no compression, no consolidation.** An addressed store has nowhere to put a sentence it cannot address, and a summary of a conversation answers no question a read can ask for. The context-overflow write was their last source and it is gone; compaction keeps the newest messages and writes no facts; the independently persisted current-work account remains available to reasoning. On the configuration this repository ships as its worked example the write already never happened — it was refused unless a model generated the summary, and the deterministic stand-in does not (#549) — so what such an operator holds is unchanged.
- **No write-time coherence.** ADR 0006 step 5 surfaced the most similar existing memories for the model to judge, which is what a store that could not compute which memory a write was for needed. The address computes it and the stated operation says what to do about it, so the note has nothing left to ask.
- **Maintenance** — capacity eviction discards the least recently read, and nothing is scored: an addressed read reaches its address without a ranking, and the score eviction used before this — salience plus a salience-scaled decay — was an age-ordered rule under another name. Nothing evicts at the capacities a decade of turns reaches (`docs/experiments/memory-frames/`), so the rule is chosen for what it does when a bound bites rather than because one is expected (ADR 0018).
- **Forgetting is decided by use, and a memory nothing has read goes first.** Eviction orders by `last_accessed`, which every read writes, and a memory that has never been read has been read longest ago — so the newest facts are what the rule pays with, which ADR 0018 states as its cost rather than as a case to soften. Salience reaches only the retention pass now, and the scoring function went with its last caller.
- Memory is never a tool: the model touches memory only through the lifecycle — the writeback is the model's single addressed-fact write path (ADR 0011, ADR 0017). ADR 0011 scopes that to the model's own surface: it unified two paths the model chose between, and it leaves platform mechanics — threshold-triggered, never model-invoked — outside. Eviction and retention are that category.

## Open questions

- Snapshot/backup of the memory file outside the pod — default post-MVP.
- Cross-agent shared memory — deferred.
- Benchmark-based evaluation harness — the read path is measured against a planted corpus with known ground truth under both embedders, and the supersession threshold against the pair set that refuted it (`docs/experiments/memory-retrieval/`); the shipped store is measured over a decade of turns beside sixteen other structures (`docs/experiments/memory-frames/`), including what a real model extracts from a message, what it declares about an assertion, and what address it reads a question onto. `docs/experiments/recall-specificity/` runs against a live agent's store, written by the agent's own turns, and scores what the shipped read step recalls from it as the question names less of what it asks about. No run measures whether a model writes back at all — that is `docs/experiments/memory-cycle/`'s subject.
- What a writeback does with a declaration it cannot trust (ADR 0018). Taking a model's declarations and always replacing are a genuine trade, and which failure is cheaper is a property of what the agent is for rather than of anything measured.
- Whether a model asked for a restriction invents one. Asked in the form the write now uses — give the restriction the statement places on the question, empty where it places none — a model supplied one on nearly every assertion that placed none, which is what collapses whole-address accuracy while the question itself stays right (`docs/experiments/memory-frames/` §Whether the address carries the arity). The forms that might not do this — a closed set of restrictions, or asking whether the statement narrows anything before asking what it narrows — are named there as different measurements, and none is measured.
- What the read step reaches resolving into a question-shaped address space, beyond the one workload that has measured it. `docs/experiments/recall-specificity/` scored the shipped step against the running binaries and it reached an address holding something on none of its 30 probes; every answer came from the widening. The earlier figure was taken resolving into the topic space, because that is the space it ran in (ADR 0018), and that run was handed the twelve attribute names it chose among — a closed vocabulary a question-shaped address does not have (`docs/experiments/memory-frames/harness/resolve.go`, as it stood before #782 retired that harness). What the new figure means for ADR 0018 and ADR 0019 is #786, an open owner decision.
- What the read step returns when a question reaches more addresses than fit. An addressed store has no ordering over the addresses under a subject and no budget to answer inside; where an ordering would have to live is the read step (ADR 0018). ADR 0019 defers one rather than specifying it — an ordering is a ranking with constants nothing calibrates — and names the condition that would reopen it: a subject read observed in production to exceed the budget.
- Whether tiered retention should run from a memory's last use rather than from its writing. The window is wall-clock and runs from the timestamp, so an idle agent drops every mid-salience memory on the turn that ends the idleness and a slow agent keeps one for a handful of turns (ADR 0006). `docs/experiments/memory-frames/` §What decides the eviction is the nearest evidence and it does not decide this: it compared last-read-time against write-age and found the age-ordered rule loses the `carried` class entirely (`0.000` against `0.775`–`1.000` for least-recently-read), but it measured which memory to discard once a hard capacity bound bites, and the same record states that capacity eviction never fires in either arm of the decade run. It measured no retention window and no turn-counted rule. Moving retention onto last use is a policy change that record does not reach, so #510 left the mechanism where it was and recorded the question here.
