# Packages

Governs the package partition: which layout of `stack-go.md` §Directory layout this project is under, what makes a boundary exist, which way imports cross it, and where a new package goes. What each package holds is `README.md` §Modules, and the rules every unit follows — what it is named for, what it may reference, when a new one is earned — are `structure.md`'s; this file is how the line around each package was drawn. Rationale: ADR 0001, ADR 0017, ADR 0004, ADR 0009.

## The layout this project is under

`stack-go.md` §Directory layout decides the layout by what the module is, not by its size: the **Service layout** governs a module that ships a binary, the **Library layout** one that ships none. This module ships `cmd/sherlock/main.go`, so it is under the Service layout, and it leaves that layout only by losing `cmd/sherlock/`. Its size settles nothing, and no line count is recorded here for that reason.

The tree is the Service layout's. Implementations sit in sub-packages of the package declaring their interface, as the layout's `internal/<domain>/<pkg>/` lists them — `internal/agent/openai/` and `internal/agent/anthropic/` behind `agent.Model`, and `internal/agent/memory/` behind `agent.Recaller`, `agent.ConversationSummarizer` and `agent.Compactor`; `find internal -mindepth 2 -type d` lists the sub-packages, these three among them. `internal/memory/sqlite/` is the one implementation that imports a driver (`modernc.org/sqlite`), and §Directory layout's "An implementation that imports a driver (`pgx`, a vendor SDK) sits outside the domain package's import graph" holds for it: `go list -deps ./internal/agent` lists neither `modernc.org/sqlite` nor `internal/memory/sqlite`, while `go list -deps ./internal/memory/sqlite` lists both.

**`service.go`** is where the layout decides a rule's scope. A domain owes one once it has behaviour of its own to offer; holding types and persisting them is not that, and neither is translating a request, composing commands or wiring a runtime. `internal/agent/service.go` is the only one, holding `Session` and `NewSession`. A domain package here that has no `service.go` is not, on that fact alone, incomplete: `internal/gateway/` translates requests and wires the runtime, and `internal/message/` and `internal/workspace/` hold shapes. Whether `internal/tool/` and `internal/config/` owe one is under "Open questions".

## Current decisions

Three cuts produce every package under `cmd/` and `internal/`, applied in that order.

- **The pod split cuts first** (ADR 0017). `internal/workspace/` and its sub-packages are the sidecar's; `internal/agent/`, `internal/gateway/`, `internal/memory/sqlite/`, `internal/tool/` and `internal/message/` are the agent container's, and `internal/config/` resolves the settings both subcommands start from. No agent-side package imports the workspace sub-tree, and the sub-tree imports no other package in this module. Its only importers elsewhere are `tools/file_read/`, `tools/file_write/`, `tools/file_list/` and `tools/shell_exec/`, separate executables rather than code either container links — which is the import graph saying what ADR 0017 decided: the agent side reaches the workspace by spawning a tool. `cmd/sherlock/` holds both sides because one binary carries both subcommands (ADR 0001), as two commands and not as a caller and a callee.
- **A domain cuts second.** A top-level `internal/<name>/` is one domain, the unit `structure.md` defines under "A domain is the unit". Size decides none of them: `internal/message/` is one eight-field struct and still a package, because `internal/gateway/` and the separately built `tools/message_send/` must agree on the JSON; `internal/workspace/` is the wire alone, so a tool links it without linking a backend (#525).
- **An implementation cuts third, and downward.** A sub-package holds either an implementation of an interface the package above declares — `internal/agent/openai/` and `internal/agent/anthropic/` for `agent.Model`, `internal/agent/memory/` for `agent.Recaller`, `agent.ConversationSummarizer` and `agent.Compactor` — or a backend nothing outside the sub-tree uses, which is `internal/workspace/files/` and `internal/workspace/shell/` behind `internal/workspace/server/`. `internal/memory/sqlite/` is the one implementation whose interface is declared by its consumer instead: `agent.ConversationMemory`, under `structure.md`'s "A consumer may declare the interface it depends on". Its parent `internal/memory/` holds no Go files, so there is no package above it to declare one ("Two boundaries the names obscure").

The direction is the rule: **no package's shipped code imports its own sub-package.** A sub-package imports upward (`internal/agent/openai/` to `internal/agent/`) or sideways inside its own sub-tree (`internal/workspace/server/` composing `files/` and `shell/`), never the reverse, and outside `cmd/sherlock/` nothing crosses the pod split. `go list -f '{{.ImportPath}} {{.Imports}}' ./...` is the check.

**Each dependency interface a domain needs has its own file, named for it**, as §Directory layout's `internal/<domain>/<name>.go` requires (#1045). A domain needs an interface when its own code is handed an implementation and calls through it, or passes it to another contract it needs: `internal/agent/` holds `Model` in `chat_model.go`, `ToolClient` in `tool_client.go`, `Recaller` in `recaller.go`, `EventSink` in `event_sink.go`, `Compactor` in `compactor.go`, `ConversationMemory` in `conversation_memory.go` and `ConversationSummarizer` in `conversation_summarizer.go`, the last a parameter of `ConversationMemory.RecordTurn` that the session carries as `Options.Summarizer`, and `internal/gateway/` holds `RuntimeFactory` in `runtime_factory.go`. `Model`'s file is not `model.go` because `stack-go.md` §0 bans that name at any level; its one method is `Chat`. An interface a package declares for other code to call is an offer, and stays where the offer is: `agent.Session`, which `internal/gateway/turn.go` calls, in `internal/agent/service.go`, and `shell.Executor`, which `internal/workspace/server/` calls and `shell.ProcessExecutor` implements, in `internal/workspace/shell/process.go`. `rg -n '^\s*(type\s+)?\w+\s+interface\s*\{' internal --glob '!*_test.go' --glob '!*.pb.go'` lists every declaration, grouped and indented ones included; it lists eleven, and the one not named here is under "Open questions".

Tests do cross, deliberately. `internal/agent/`'s tests import `internal/agent/memory/`, `internal/message/`'s import `internal/tool/tooltest/`, and `tests/` wires both sides of the pod. The seam is a property of the shipped binaries; a test binary is where the halves are put back together on purpose.

**The composition site runs from `cmd/sherlock/` into `internal/gateway/`'s `Factory.New`.** `stack-go.md` §Project envelope places the site in `cmd/<binary>/main.go` unless a test outside `cmd/<binary>/` has to reach it, and then in a package `main.go` calls. That exception is this tree's case. `tests/` (`TestEndToEnd_MVPScenario`, `TestGateway_EndToEnd` among them) and `internal/gateway/`'s external tests (`package gateway_test`) build a `gateway.Factory` and run the wired runtime, and none of them can import `package main`. `Factory.New` opens the store with `sqlite.OpenConversation` (`sqlite.OpenInitializedConversation` under `--require-store`), calls `agent.NewSession` and constructs the three `internal/agent/memory/` hooks. The binary reaches it through `main.go`'s `NewRootCommand`, then `newAgentFactory` and `startQueue` in `cmd/sherlock/agent.go`, a file of the same `package main`, then `gateway.NewQueue`, which calls `Factory.New`. `cmd/sherlock/` constructs what the tests substitute — the model client, the embedder, the `*tool.Registry` and the token verifier — and hands the first three to the factory as fields. #710 built the alternative, the wiring moved into `cmd/sherlock/`, and measured what the exception names: each test package would hold a copy of the wiring, and `TestEndToEnd_MVPScenario` and `TestGateway_EndToEnd` would go on passing after the shipped wiring broke.

A capability is not a package. Tools arrive as `tools/<name>/` directories the platform spawns from their manifests, so adding one changes no import (ADR 0009, ADR 0001).

## Two boundaries the names obscure

- **`internal/memory/sqlite/` and `internal/agent/memory/` are not one thing split in two.** `internal/memory/sqlite/` is the memory store, and it depends on the agent domain one way: it imports `internal/agent/`, and nothing under `internal/agent/` imports it (#943). It satisfies `agent.ConversationMemory`, the interface the agent declares as its consumer (`structure.md`, "A consumer may declare the interface it depends on"), in the agent's own types. Its parent `internal/memory/` holds no Go files since the addressed memory domain it held was deleted (#1018); the path stays because the research harnesses import it, and moving it would change `research/chained-recall/study/live_test.go`, whose SHA-256 `research/memory-encoding/attributed/preregistration.md` pins. `internal/agent/memory/` holds compaction, episodic synthesis and source-linked recall, and imports `internal/agent/` and `internal/tool/` only. The shared word names the domain the hooks serve, not a parent and a child. `internal/agent/`'s only shipped internal import is `internal/tool`, and keeping that true is what the sub-package is for.
- **The provider clients are packages because the layout places implementations there, and their size no longer decides it.** `stack-go.md` §Directory layout lists the implementations of a dependency interface under `internal/<domain>/<pkg>/` at any size; its "One file vs several" sizes the files inside that sub-package — one file per implementation up to roughly 300 lines with no private helpers worth isolating, several past that — and does not choose between a file and a package. Neither client imports a vendor SDK (`go list -f '{{.Imports}}'` on both lists only the standard library, `internal/agent` and `internal/tool`), so the driver rule does not reach them. Names would keep them apart anyway: both declare `Config`, `New`, `toWireMessages` and `toWireTools`, so one package cannot hold both without renaming half of one. The same interface still ships as a file here — `internal/agent/scripted.go`, sixty lines of `agent.Model` — which is under "Open questions". Neither client is imported by the loop it serves; `cmd/sherlock/model_provider.go` selects one from the configured protocol (ADR 0004).

## Where a new package goes

Answer in order. The first yes places it.

1. Does the sidecar run it? It goes under `internal/workspace/`, and no agent-side package may import it.
2. Does it implement an interface an existing package declares? It goes in a sub-package of that package, as `stack-go.md` §Directory layout lists implementations under `internal/<domain>/<pkg>/`; one that imports a driver must, by that section's driver rule.
3. Must two separately built programs agree on it? It is a top-level `internal/<name>/` holding the shape and no behaviour, as `internal/message/` and `internal/workspace/` do.
4. Has it earned a domain, as `structure.md` states under "A new domain is earned"? It is a top-level `internal/<name>/`, and its implementations nest beneath it.
5. Otherwise it is a file in the package that uses it. One consumer and no interface is not a boundary.

A new capability usually answers no to all five, because it is a tool and not Go code the platform links.

## Open questions

- **Two obligations of `stack-go.md` §Directory layout that the tree does not meet.** The layout lists implementations under `internal/<domain>/<pkg>/`, and `internal/agent/scripted.go` implements `agent.Model` as a file in the domain package; it imports no driver, so only the inventory and not the driver rule reaches it. And a domain owes a `service.go` once it has behaviour of its own to offer: `internal/tool/` offers tool calls through the exported `*tool.Registry`, and `internal/config/` resolves settings, and neither has one. Moving code is out of scope for the change that adopted the layout (#1030).
- **`agent.Embedder` is declared by a package that neither uses nor implements it.** It sits in `internal/agent/conversation.go`, and no code in package `agent` names it outside that declaration. Its users are `internal/memory/sqlite/` (the `embedder` field of `Store` in `sqlite.go`, `OpenConversation` and the `s.embedder.Embed` call in `conversation.go`), `internal/gateway/`'s `Factory.Embedder`, and `cmd/sherlock/model_provider.go`'s `newEmbedder`; its shipped implementers are `internal/agent/openai/`'s `Embedder` and `cmd/sherlock/mock_model.go`'s `mockEmbedder` (`rg -n 'Embedder|\.Embed\(' internal cmd --glob '!*_test.go'`). Under §Directory layout's "the side that needs the behaviour declares the contract", its likely home is `internal/memory/sqlite/`; moving it renames an exported identifier, which #1045 left out of scope.
- **`internal/tool/tooltest/` is produced by none of the three cuts.** It implements no interface `internal/tool/` declares and its consumers are elsewhere — the tests of `internal/gateway/` and `internal/message/`. It nests under the package whose manifests it reads, which is a fourth reason for a sub-package that the rule above does not state.
- **No ADR states the pod-split import rule.** ADR 0017 decides the two containers. That no agent-side package may import `internal/workspace/` follows from it, and is written down only here and in the import graph.
