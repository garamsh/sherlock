=== 6. the timeout fix: the test that fails without it ===
`fix: kill the process group when a command times out` is in this branch because
the privileged family cannot be green without it, not because it was found on the
way past. Reverting that one commit's change to process_linux.go and running the
same privileged command:

  git show <the fix> -- internal/workspace/shell/process_linux.go | git apply -R -

--- FAIL: TestProcessExecutor_Timeout (5.00s)

With the fix, the same case passes in 0.10s (section 2 above). The test is not
new: TestProcessExecutor_Timeout has asserted `elapsed < 3s` all along, behind
requireRoot, so it is the only case in the package that exercises a timeout at
all and no run ever reached it. The defect is not privilege-specific — the shim,
the shell and the command inherit the same pipe in single-account mode too — it
is only that the sole test for it needs root.

=== 7. a finding the check produced, not part of this branch's change ===
The privileged job runs with the container runtime's default capability set plus
SYS_ADMIN. Running the same target under the capability set the deployment gives
the workspace container instead — `cap_drop: ["ALL"]`, `cap_add: ["SETUID",
"SETGID", "CHOWN", "SYS_ADMIN"]` (deploy/local/docker-compose.yml) — fails:

  --- FAIL: TestProcessExecutor_Timeout (5.01s)
          Error:      "5.012587554s" is not less than "3s"
  exit 2

Adding CAP_KILL to that set makes it pass; that is the whole difference, measured
both ways. Signalling a process that runs as a different uid needs CAP_KILL, and
root does not bypass the check when the capability is not in its effective set —
so in the shipped deployment the executor cannot signal the child it dropped to
the exec UID, and ADR 0008's "on expiry it is SIGKILLed" does not hold there.
That is true of the single-child kill this branch replaced as much as of the
process-group kill it added.

Not fixed here: the deployment's capability set is a separate change from #604,
and by the rule that a fix which merely happened first is out of scope, it is
reported rather than made. The check that found it is the one #604 asked for.
